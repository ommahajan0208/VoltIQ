# VoltIQ Website Guide

## 1. What VoltIQ does

VoltIQ is a local-first household-energy analysis workspace. It keeps source time, missing readings, dataset versions, model runs, detector thresholds, review notes, and generated artifacts traceable. The website supports two modes:

- **Synthetic demonstration**: a fixed illustrative fixture for exploring the interface. It does not represent real readings and does not provide scientific evaluation metrics.
- **Local API mode**: reads datasets, runs, forecasts, scores, jobs, and reports from the local backend.

The application works with 15-minute source intervals. A candidate anomaly is a review prompt, not a confirmed equipment fault or appliance identification.

## 2. Global navigation and controls

The workspace shell appears on every analysis page.

### Sidebar navigation

| Group | Link | Route | Use case |
|---|---|---|---|
| Analysis | Overview | `/overview` | Review KPIs, the main timeline, event candidates, and evidence coverage. |
| Analysis | Consumption | `/consumption` | Explore measured channels, daily energy, missingness, and night comparisons. |
| Analysis | Forecasting | `/forecasting` | Inspect historical forecasts or generate a forecast after the dataset endpoint. |
| Analysis | Anomalies | `/anomalies` | Filter, sort, export, and review candidate periods. |
| Workspace | Data & pipeline | `/data` | Select datasets, inspect quality, upload readings, preprocess data, and start runs. |
| Workspace | Models & evaluation | `/models` | Inspect run identity, saved runs, held-out metrics, threshold previews, experiments, and bundles. |
| Workspace | Reports | `/reports` | Configure a frozen PDF report and export observations or events as CSV. |

The **VoltIQ** logo returns to the landing page. On small screens, the menu icon opens the same navigation in a modal drawer.

### Dataset selector

The **Dataset** selector changes the active registered dataset. Changing it resets the selected run, date range, forecast origin, selected job, report, and pagination cursor. A compatible saved run may then be selected automatically.

### Run selector

The **Run** selector chooses a saved analysis run for the selected dataset. Only succeeded runs can be selected. Changing the run resets the date range, forecast origin, and event pagination cursor.

### Date range and scope

On pages that use a ready dataset, the top toolbar provides:

- Two date inputs for an inclusive start and end date.
- **Apply**: validates the dates, checks that they are inside dataset coverage, and reloads page data.
- **All day**: analyzes the complete selected date range.
- **Overnight · 00–05**: limits analysis to source household time from midnight through 05:00.

Invalid or out-of-coverage dates show a validation notice instead of changing the active range.

### Activity

The **Activity** button opens processing activity and shows queued, running, cancelling, succeeded, and failed worker jobs.

Inside a job card:

- **Request cancellation** asks the backend worker to cancel an active API-mode job.
- **Download completed artifact** downloads an artifact generated by a succeeded job.

A progress bar is shown only when the backend reports completed and total counts. The interface does not invent progress or completion times.

### Appearance and motion

- The waves icon toggles reduced animation.
- The moon/sun icon switches between dark and light themes.
- The mode-banner link switches between **Connect local API** and **Open synthetic demo** for the current route.

## 3. Landing page — `/`

The landing page introduces the product and provides the main entry paths.

- **Explore the workspace** opens Data & pipeline and begins from dataset selection.
- **Add your readings** opens Data & pipeline with the upload wizard ready in API mode.
- **Open synthetic demo** opens Overview using the fixed demonstration fixture.
- **Play/Pause history** starts or pauses the illustrative overnight trace. It respects reduced motion and pauses when the browser tab is hidden.

The landing waveform is illustrative: cyan is observed power, lavender is a forecast range, and amber is a candidate interval.

## 4. Overview — `/overview`

Overview is the high-level dashboard for a selected dataset and run.

### KPI cards

- **Observed energy**: sum of valid observed readings in kWh.
- **Overnight observed energy**: valid observed energy from 00:00–05:00 source time.
- **Candidate events**: distinct residual events intersecting the selected range.
- **Eligible scored intervals**: selected 15-minute intervals eligible for scoring.

### Buttons and interactions

- **Open forecasting** opens Forecasting with the current context.
- **Explore consumption** opens Consumption with the current context.
- **View all** opens the complete Anomalies list.
- Clicking an amber timeline marker opens that event’s evidence page.
- Selecting a timeline range opens Consumption with that source-time range.
- Selecting an event row exposes its candidate details where supported.

The evidence-coverage panel separates complete observations, partial observations, and missing or quality-excluded intervals. Excluded time is not treated as normal consumption.

## 5. Consumption — `/consumption`

Consumption is the measured-data explorer. It preserves gaps instead of filling missing readings with zero.

### Controls

- **Measured channel** chooses Active power (kW), Reactive power (kVAR), Voltage (V), or Current (A).
- **Candidate overlay** overlays scores and candidate events. It is disabled until a run is selected.
- **Reset range** restores full dataset coverage and all-day scope.
- **Export CSV** exports the loaded observation rows. Demo mode downloads a synthetic CSV; API mode submits an export job.

### Charts and panels

- Selecting a chart range focuses the analysis on that source-time interval.
- Clicking an event marker opens its evidence page.
- Clicking a **Daily observed energy** day sets the active range to that day.
- **Daily observed energy** shows observed kWh, coverage, and valid-bin counts.
- **Median daily profile** shows median power for each 15-minute slot and contributing counts.
- **Compare the quiet hours** lets users select up to three days aligned from 00:00–05:00.
- **Measured circuits & remainder** shows aligned sub-meter energy when required circuit channels are available.

## 6. Forecasting — `/forecasting`

Forecasting separates historical backtesting from forecasts beyond the last known reading.

### Mode buttons

- **Historical backtest** chooses an origin in known history. Observed targets and held-out metrics can be shown.
- **After dataset endpoint** forecasts beyond the last reading. Future target truth is unavailable, so accuracy is not reported.

### Forecast controls

- **Horizon** chooses 15 minutes, 1 hour, or 4 hours.
- **Engine** chooses Chronos-Bolt Tiny, Persistence baseline, Seasonal naive baseline, or the synthetic illustration in demo mode.
- **Previous origin** and **Next origin** move a historical origin by 15 minutes.
- The **Origin selector** chooses a demo origin or an exact historical datetime in API mode.
- **Show baselines** toggles persistence and seasonal-naive comparison lines.
- **Generate missing inference** submits a forecast job for an existing run.
- **Create inference run** creates an inference run when no run is selected, then submits the job.
- **Export CSV** exports forecast points for the selected origin and is disabled when the returned origin does not match the request.

The chart shows causal context, q10/q50/q90 forecast values, and observed targets when historical ground truth exists. The q10–q90 band is a forecast range, not a guaranteed confidence interval.

## 7. Anomalies — `/anomalies`

Anomalies lists candidate intervals produced by a saved detector threshold. It does not claim that a candidate is a verified fault.

### Filters

- **Detector**: Chronos one-step residual or Statistical reference deviation. The optional autoencoder is disabled unless an evaluated experiment supports it.
- **Direction**: All directions, Higher, Lower, or Mixed.
- **Review**: All statuses, Unreviewed, Reviewed, or Needs follow-up.
- **Sort**: Newest first, Highest score, or Longest duration.
- **Min peak score** filters candidates below the entered score.
- **Reset** restores direction, review, sort, minimum score, and pagination defaults.

### Buttons and interactions

- **Export CSV** exports the currently filtered event list.
- Clicking an event row selects it and displays an inline evidence preview.
- **Next page** loads the next cursor page.
- **Return to first page** clears the cursor.
- **Open full evidence** opens `/anomalies/[id]` for the selected candidate.

If a detector is not calibrated, the page explains that validation scores and a saved threshold are required before candidates can be interpreted.

## 8. Event evidence — `/anomalies/[id]`

This page is the detailed evidence and human-review workspace for one candidate interval.

### Evidence

- **Observed and expected consumption** compares measured values with forecast and reference values while retaining missing and excluded intervals.
- **Residual evidence** shows the score and saved validation threshold.
- **Interval evidence table** lists source time, observed kW, forecast kW, reference kW, score, and quality for every interval.

### Review controls

- **Review status** chooses Unreviewed, Reviewed, or Needs follow-up.
- **Plain-text note** accepts up to 2,000 characters.
- **Save review** saves status and note. API mode uses revision checks; demo notes last only for the browser session.
- **Copy draft** copies the unsaved note after a revision conflict.
- **Load latest review** discards the conflicting draft and loads the newest server review.
- **Prepare event evidence report** opens Reports with the event preselected.

Source-time links in the evidence table open Forecasting at the corresponding historical origin. Review status is workflow metadata, not anomaly ground truth.

## 9. Data & pipeline — `/data`

Data is the starting point for registering readings and preparing analysis.

### Dataset actions

- Clicking a dataset row makes it active and resets incompatible run and date context.
- **Add dataset** opens the upload wizard. Actual registration is unavailable in synthetic mode.
- **Open consumption** opens the measured-data explorer.
- **Queue required evaluation** creates a held-out evaluation job when chronological history and evaluation capability are sufficient. It is disabled in demo mode or when prerequisites are missing.
- **Create inference run** creates an inference run when a ready checkpoint and 192 eligible context bins are available.

### Upload wizard

The wizard stages are Select, Map, Preview, Configure, Process, and Analyze.

1. **Select**: choose a CSV/TXT file; archives and files above 200 MiB are rejected. **Register upload** uploads the file.
2. **Map**: choose generic minute-power or native UCI. Select delimiter, timestamp format/columns, power column/unit, and optional channels. **Validate mapping** sends the mapping and creates a preview.
3. **Preview**: inspect parsed rows, diagnostics, and invalid-row counts. **Edit mapping** returns to Map. **Confirm interpretation** accepts the preview.
4. **Configure**: choose the processing profile and optional start date. **Start PySpark processing** submits preprocessing.
5. **Process**: follow backend-reported worker status. After success, **Review dataset quality** closes the wizard and returns to quality results.
6. **Analyze**: use **Queue required evaluation** or **Create inference run** after the dataset is ready.

## 10. Models & evaluation — `/models`

Models explains which configuration produced a result.

- Clicking a succeeded saved-run row selects it. Runs from another dataset version or unfinished runs are disabled.
- The immutable configuration panel shows run ID, dataset version, engine, checkpoint revision, evaluation kind, hashes, test interval, and threshold.
- **Queue preview** submits an exploratory validation-threshold preview for the selected run and quantile. It is disabled without a run, in demo mode, or while busy.
- **Reset preview** returns the validation quantile to `0.99`.

The evaluation table reports MAE, RMSE, MASE, q10–q90 coverage, target count, skipped count, and split-qualified rows by horizon. Optional experiments and Colab bundle imports stay separate from primary interval KPIs.

## 11. Reports — `/reports`

Reports creates shareable outputs tied to a selected run, range, event selection, and review snapshot.

Select sections such as consumption, forecasting, events, notes, quality, and methodology. The preview is a draft; generation freezes the active filters and review snapshot.

- **Print synthetic preview** opens the browser print dialog for the demo preview.
- **Generate frozen PDF** submits an API job and requires selected sections plus a valid overview.
- **Export observations CSV** exports observations for the selected filters.
- **Export events CSV** exports selected events, including review status and notes when notes are included.
- **Download PDF** downloads a completed saved report artifact.
- Clicking a recent saved report opens its frozen artifact/status.

A generated report remains tied to its saved run and captured filters even if current page filters change later.

## 12. Loading, errors, and unavailable states

- **Retry** refetches a failed resource.
- Empty states explain why data is unavailable and what action can produce it.
- Disabled buttons generally indicate a missing capability, selected run, calibration, required history, or API mode.
- API errors are not silently replaced with synthetic data.
- The global error page provides **Try again**.
- The not-found page provides a link back to **Data & pipeline**.

## 13. Recommended user journeys

### Explore the demo

1. Open the landing page.
2. Choose **Open synthetic demo**.
3. Review Overview, then explore Consumption and Forecasting.
4. Inspect Anomalies and Reports to understand the review and reporting states.

### Analyze a real file

1. Open Data & pipeline in local API mode.
2. Choose **Add dataset**.
3. Register the CSV/TXT file, map columns, validate, confirm the preview, and start processing.
4. Review quality and choose **Queue required evaluation** or **Create inference run**.
5. Select the resulting succeeded run.
6. Use Overview, Consumption, Forecasting, and Anomalies to inspect results.
7. Review candidates, save notes, and generate a frozen report.

### Review an anomaly

1. Open Anomalies from the sidebar or Overview.
2. Filter by detector, direction, review status, sort, or minimum score.
3. Select an event and choose **Open full evidence**.
4. Compare observed, forecast, reference, score, and quality values.
5. Set a review status, add a note, and choose **Save review**.
6. Choose **Prepare event evidence report** when a shareable record is needed.

## Peak load

Route: `/peak-load`

This page analyzes the selected dataset and date range without requiring a forecasting run. It uses valid 15-minute active-power readings to calculate a dynamic percentile threshold and groups adjacent threshold crossings into peak events.

- **Peak demand** shows the highest observed active-power value in the selected range.
- **Dynamic threshold** shows the percentile threshold used to identify peaks.
- **Peak periods** counts grouped peak events, not individual readings.
- **Excess over median** estimates energy above the selected period's median demand; it is an evidence measure, not a guaranteed savings estimate.
- **Demand chart** displays observed demand, the dynamic median baseline, and the peak threshold.
- **Peak event table** lists each event's start, end, duration, peak demand, average demand, energy, and excess-over-median evidence.
- **Open recommendations** opens the rule-based recommendation page for the selected run when one is available.

Incomplete intervals remain visible in the chart but are excluded from peak detection and energy totals. The page is intended for demand-pattern investigation, not appliance identification.

## Recommendations

Route: `/recommendations`

This page turns measured evidence into independent, explainable review prompts. It does not calculate or display a weighted recommendation score.

Each recommendation card shows:

- **Severity**: the urgency of the review prompt under the rule that fired.
- **Evidence**: the values that caused the rule to fire, such as peak count, threshold, coverage, or anomaly count.
- **Why this appeared**: a plain-language explanation of the transparent rule.
- **Suggested next action**: an operational follow-up, such as reviewing flexible loads or improving data coverage.
- **Confidence**: confidence in the evidence pattern, not certainty about the cause.
- **Limitation**: the interpretation boundary; recommendations do not prove an appliance fault or guaranteed savings.

Current independent rules cover repeated high peaks, concentrated peak windows, overnight peak activity, repeated forecast deviations, and incomplete measurement coverage. A rule may appear alongside other rules because each rule is evaluated separately.
