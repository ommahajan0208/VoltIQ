# Backend handoff

The frontend follows `/api/v1` endpoint paths from the supplied backend specification. Because no server/schema was supplied, confirm the DTOs and mutation bodies before treating these integrations as complete.

## Transport

The browser uses same-origin `/api/v1/*`. `src/app/api/v1/[...path]/route.ts` proxies to server-only `BACKEND_URL` and supplies server-only `APPLICATION_TOKEN` through `X-Application-Token`. Confirm this header name with the backend team; it was not fixed by the specification. Mutation requests validate loopback Host and same Origin. Requests stream to the backend; upstream downloads preserve content type/disposition. The proxy has a 30-second request timeout. The backend owns size, content, schema and worker validation.

No model endpoint or cloud reading upload is called by the frontend. Live mode defaults to the local API and does not fall back to fixtures on any error.

## Required envelopes

Every JSON response consumed by the current adapter has this form:

```json
{
  "data": [],
  "meta": {
    "schema_version": "2.0",
    "dataset_id": "ds_example",
    "dataset_version": "version_example",
    "run_id": "run_example",
    "time_basis": "source_local_naive",
    "from": "2007-05-01T00:00:00",
    "to": "2007-05-02T00:00:00",
    "next_cursor": null
  }
}
```

Inventory responses use arrays; single-entity responses use objects. Analytical responses must contain matching dataset IDs; run-bound responses must additionally contain matching run IDs. A returned version, when present, must match the requested version. Jobs and inventory do not require a measurement identity. Missing analytical identity prevents a panel from rendering.

Error envelope: `{ "error": { "code": "...", "message": "...", "details": {}, "request_id": "..." } }`.

## Frontend DTO expectations

`src/lib/types.ts` is the complete list of fields consumed by the UI. The most important assumptions to align are:

| Resource | Expected data |
| --- | --- |
| datasets | Array of summaries: `id`, `version`, `label`, source/status, coverage bounds and capability booleans |
| runs | Array of immutable runs with dataset/version, model revision, evaluation kind, test bounds, saved threshold and hashes |
| series | Array of canonical bins containing the requested channel, source start/end, active coverage and null-preserving observations |
| scores | Array of per-bin scores with explicit `score_unit`, threshold, status and nullable candidate flag |
| events | Array of complete event summaries with authoritative `dataset_id`, `run_id`, `detector`, review revision and optional clipped visible bounds |
| overview | Full-resolution KPI object; the frontend never derives real KPI totals from display buckets |
| profiles | Object with `daily`, `slots`, `circuits`; daily energy/coverage and slot valid counts are generated by the backend |
| quality | Selected/invalid/duplicate counts, complete/partial/missing bins, coverage, optional measured ETL seconds and gap spans |
| metrics | Array with model, horizon in 15-minute bins, MAE/RMSE/MASE, empirical quantile coverage and eligible/skipped counts |
| forecasts | Array of dated quantiles/eligible actuals with origin, horizon and baseline values; no known future actuals in endpoint mode |
| job | Object with state/stage, actual completed/total counts, errors and returned artifact/run/report IDs where applicable |
| report | Object with frozen identity/range/status and completed registered `artifact_ids` |

If the backend chooses different serializations, adapt at `src/lib/api/client.ts`, not independently in each page.

## Mutation shapes to confirm

- Upload: multipart `file`; response data `{id, detected_columns, preview}`.
- Mapping PUT: `profile`, `delimiter`, timestamp format/column(s), `active_power: {column, unit}`, and optional explicit channel mappings.
- Mapping PUT response: `{preview, diagnostics, invalid_rows}`. `preview` must show the interpreted values. The wizard intentionally blocks confirmation if the backend returns no parsed preview.
- Preprocess POST: `{profile: "development"|"final"|"full", start_date}`; response `{job_id}`.
- Runs POST: `{dataset_id, dataset_version, model_id, evaluation_kind, config}`; response `{run_id, job_id}`.
- Forecast POST: `{origin_mode, origin, horizon, model_id}`; response `{job_id}`.
- Review PATCH: `{status, note, expected_revision}`; response updated `{status, note, revision}`. A 409 should return `error.details.current_review` so the newer note/revision can be displayed beside the preserved draft.
- Threshold preview POST: `{validation_quantile, exploratory: true}`; response `{job_id}`.
- Experiment POST: an allowlisted `type: "autoencoder"`, dataset/version, base run and bounded training configuration.
- Bundle import: multipart `file`; response `{job_id}` after safety/compatibility validation.
- Report POST: frozen run, range, scope, selected sections/event IDs, optional forecast origin/horizon/model, and `format: "pdf"`; response `{report_id, job_id}`.
- Export POST: dataset/run, kind and explicit filters; response `{job_id}`. Completed jobs expose `artifact_id` and preferably `row_count`.

Job-creating JSON mutations send `Idempotency-Key`. The adapter retains the key for an identical uncertain request until a successful response; this memory is session-local. Across a browser refresh, durable recovery uses returned job IDs and the backend inventory, not a browser-stored copy of readings.

## Important scientific boundaries

All thresholds, event grouping, real profiles, full-resolution energy, evaluation metrics and report totals belong to persisted backend artifacts. JavaScript only formats real results and changes views. The synthetic adapter is separately imported only for explicit demonstration and provides illustrative filtered responses.

Time axes use a deterministic numeric plotting coordinate, then explicitly format offset-free source labels. This is an internal chart representation, not an assertion that measurements occurred in UTC. The request/export timestamps themselves remain source strings.

Event evidence first fetches the authoritative event and run; series/score requests then use that run’s dataset version. An unsupported window detector receives a setup explanation rather than a fabricated primary-interval explanation.
