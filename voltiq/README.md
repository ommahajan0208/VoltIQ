# VoltIQ - frontend

Local Next.js application with a midnight cyan design, shared analytical components, explicit synthetic demonstration and a server-side proxy for the FastAPI backend in `../backend/`.

## Run locally

Use Node.js 22 or newer. Node.js 24 was used for the checks below.

```bash
npm ci
npm run dev
```

Open `http://127.0.0.1:3000`. The application binds to loopback. To inspect all pages without a backend, explicitly open `http://127.0.0.1:3000/overview?mode=demo`, or choose the synthetic demo from the landing-page run picker.

For real API mode, copy `.env.example` to `.env.local`, set `BACKEND_URL` and any configured local `APPLICATION_TOKEN`, and start the FastAPI service and worker using `../instructions.md`. The default backend address is `http://127.0.0.1:8000`. Dataset processing and model weights are one-time backend setup steps.

Production:

```bash
npm run build
npm start
```

## Shared behavior

- App Router with a shared workspace shell; responsive styles for mobile, tablet and desktop.
- Locally installed Inter fonts and Lucide icons; no runtime remote font dependency.
- TanStack Query cache keys include mode, dataset version, run and the relevant filters. Superseded GETs receive an abort signal.
- Analytical response metadata is checked before rendering; missing/wrong dataset or run identity is rejected.
- Shareable filters live in the URL. Theme and motion preferences are the only values stored in `localStorage`.
- Source measurement labels are offset-free. Date arithmetic preserves source wall-clock time; inclusive calendar ends become next-day exclusive API bounds.
- ECharts modules load on demand, use SVG rendering, resize through `ResizeObserver` and dispose on unmount. Exact source-time labels are formatted explicitly rather than using the viewer’s timezone.
- Tables provide an accessible alternative to time-series charts. Navigation, review inputs and replay controls use labelled native controls; dialogs use Radix focus management.
- Reduced-motion preferences reach Motion, CSS and chart behavior. Replay starts paused and stops advancing while the tab is hidden.
- Jobs show server stages/counts, not timer-generated progress. Selected job IDs survive navigation and refresh in the URL. Cancellation remains a request until the server reports a terminal state.
- Job submissions reuse an idempotency key after an uncertain failed response during the current session.
- API errors remain API errors. The app never silently switches to synthetic data.

## Synthetic demonstration

`src/fixtures/synthetic.json` is deterministic illustrative data generated by `scripts/create-fixture.py`. It is not UCI readings or actual Chronos output. The UI keeps a synthetic banner visible, calls the forecasting engine synthetic, omits scientific evaluation metrics and labels exported CSVs accordingly.

Demonstration review notes live only in memory, survive route changes and reset on refresh. In API mode, reviews use `PATCH /events/{id}/review` with `expected_revision`; drafts remain intact on failure.

## API integration status

`contracts/backend-openapi.json` is exported from the current FastAPI server. `src/lib/api/generated.ts` contains its generated endpoint paths and query parameter types. Resource DTOs in `src/lib/types.ts` still need full backend response-model typing.

After backend route changes, re-export `contracts/backend-openapi.json` from FastAPI and regenerate:

```bash
npm run api:generate
```

See `docs/API_INTEGRATION.md` for expected envelopes, mapping preview fields, job results, review conflicts and the proxy token header. The generated schema currently leaves `data` generic rather than inventing authoritative backend DTO definitions.

## Validation

```bash
npm run typecheck
npm test
npm run build
```

TypeScript, 35 focused tests and the production build passed after generating the FastAPI client. The tests cover source dates, CSV escaping, synthetic missingness and event consistency, future targets, review conflicts, scientific cache keys, response identities, uncertain job retries and the local proxy boundary. See `../PROGRESS.md` for the backend validation status and remaining acceptance gates.

The synthetic overview and event-detail pages were visually inspected in the local browser. Real upload-to-analysis browser QA, the official 250,000-row Spark run and held-out Chronos evaluation remain unverified. Remaining work is recorded in `../PROGRESS.md`.

## Structure

```text
src/app/                  routes, shell layouts and local API proxy
src/features/             page workflows
src/components/           shared shell, charts, tables, dialogs and job controls
src/lib/                  dates, URL state, cache/identity rules and API adapter
src/fixtures/             explicitly synthetic saved demonstration
contracts/                provisional OpenAPI and generated client input
tests/                    focused correctness tests
docs/specs/               unchanged copies of all six supplied specifications
```

Spark processing and neural-network inference run in the separate backend worker, not in the browser.
